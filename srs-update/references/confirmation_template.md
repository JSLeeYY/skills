# 确认签批文档模板结构

## 文档命名规范

格式：`YYYYMMDD_模块名_完整功能确认.md`

示例：`20260318_动态成本核算_完整功能确认.md`

## 文档结构

### 1. 文档头部元数据

```markdown
# [模块名称]模块 — 完整功能确认签批文档

**文档编号**：SIGN-[模块简称]-YYYYMMDD
**模块名称**：[模块名称]
**涉及页面**：[页面列表]
**涉及文件**：[文件列表]
**SRS对应章节**：§[章节号]
**文档日期**：YYYY-MM-DD
**状态**：待确认
```

### 2. 说明部分

说明确认原则：以【实际实现描述】为准，确认后将以此描述更新SRS对应内容。

### 3. 功能点确认部分

每个功能点包含以下字段：

```markdown
### 功能点[序号] — [功能名称]

**【功能编号】**：FUNC-[模块]-[序号]

**【SRS原文描述】**：

> [从SRS中复制的原文描述]

**【实际实现描述】**：

[详细描述实际页面的实现情况]

**【差异说明】**：

[说明SRS与实际实现的差异]

**【您的确认】**：□ 同意  □ 不同意

**【备注】**：
```

### 4. 汇总总览部分

```markdown
## 汇总总览

### 功能点实现状态汇总表

| 功能点 | 功能描述 | SRS覆盖状态 | 实现状态 |
|-------|---------|-----------|---------|
| FUNC-XXX-001 | [功能描述] | ✅ SRS已描述 | ✅ 已实现 |

**SRS需要更新的主要内容**：

1. [列出需要更新的要点]
```

### 5. 签批部分

```markdown
**签批人**：_______________

**签批日期**：_______________
```

## 填写指南

### SRS原文描述
- 直接从SRS文档中复制相关章节的原文
- 使用引用格式（> 开头）
- 保持原文完整性

### 实际实现描述
- 详细描述实际页面/功能的实现情况
- 包含具体的交互细节、字段说明、布局描述
- 使用清晰的结构化描述（如使用列表、表格）

### 差异说明
- 明确指出SRS描述与实际实现的不同之处
- 说明差异的原因（如需求变更、技术限制、优化改进等）
- 标注新增功能或删减功能

### 确认选项
- 使用 `□ 同意  □ 不同意` 格式
- 确认后改为 `☑ 同意` 或 `✓ 同意`
- update_srs.py 脚本会识别 `同意`、`✓`、`☑` 标记

## 注意事项

1. **一次一个模块**：每个确认文档只针对一个功能模块
2. **完整性**：确保所有功能点都有对应的确认项
3. **准确性**：实际实现描述必须与页面实现完全一致
4. **可追溯性**：保留功能编号以便后续追踪
