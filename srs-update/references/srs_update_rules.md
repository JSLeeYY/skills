# SRS 更新规则与指南

## 更新流程

```
实际实现 → 创建确认文档 → 签批确认 → 解析确认项 → 更新 SRS
```

### 1. 创建确认文档

使用 `create_confirmation_doc.py` 生成确认文档模板：

```bash
python scripts/create_confirmation_doc.py <模块名> <SRS章节> <输出目录>
```

示例：
```bash
python scripts/create_confirmation_doc.py 监理人员动态 §5 ./需求确认签批
```

### 2. 填写确认文档

- 从 SRS 复制原文描述到【SRS原文描述】
- 详细描述实际实现到【实际实现描述】
- 说明差异到【差异说明】
- 标记确认状态：`☑ 同意` 或 `✓ 同意`

### 3. 更新 SRS 文档

使用 `update_srs.py` 自动更新 SRS：

```bash
python scripts/update_srs.py <确认文档路径> <SRS文档路径> [--no-backup]
```

示例：
```bash
python scripts/update_srs.py ./需求确认签批/20260318_动态成本核算_完整功能确认.md ./Operations_and_Management_SRS_Final_V11.md
```

## 更新原则

### 1. 精确匹配原则

- 脚本通过【SRS原文描述】在 SRS 文档中查找精确匹配的文本
- 只有完全匹配才会执行替换
- 如果找不到匹配，会输出警告信息

### 2. 确认状态识别

脚本只处理以下确认状态的功能点：
- `同意`
- `✓`
- `☑`

未确认或标记为"不同意"的功能点会被跳过。

### 3. 自动备份机制

- 默认在更新前自动备份 SRS 文档
- 备份文件命名格式：`[原文件名].backup_YYYYMMDD_HHMMSS`
- 可使用 `--no-backup` 参数跳过备份

### 4. 替换规则

- 用【实际实现描述】完整替换【SRS原文描述】
- 保持 SRS 文档的其他内容不变
- 一次性处理所有已确认的功能点

## 注意事项

### 1. SRS 原文描述的准确性

**关键**：【SRS原文描述】必须与 SRS 文档中的文本完全一致，包括：
- 空格、换行符
- 标点符号
- 格式标记（如 Markdown 语法）

**建议**：直接从 SRS 文档复制粘贴，避免手动输入。

### 2. 实际实现描述的完整性

【实际实现描述】应该：
- 完整描述实际功能实现
- 包含所有关键细节（字段、交互、布局等）
- 使用清晰的结构化格式
- 可以比原 SRS 描述更详细

### 3. 处理未匹配的情况

如果脚本输出 `⚠ 未找到匹配内容`：
1. 检查【SRS原文描述】是否与 SRS 文档完全一致
2. 确认 SRS 文档路径是否正确
3. 检查 SRS 文档是否已被修改

### 4. 版本控制建议

- 在更新 SRS 前提交当前版本到 Git
- 更新后检查 Git diff 确认修改正确
- 保留确认文档作为变更记录

## 常见问题

### Q: 如何处理多个模块的更新？

A: 为每个模块创建独立的确认文档，逐个执行更新脚本。

### Q: 更新失败如何恢复？

A: 使用自动生成的备份文件恢复：
```bash
cp [SRS文档].backup_YYYYMMDD_HHMMSS [SRS文档]
```

### Q: 可以批量更新多个确认文档吗？

A: 当前脚本不支持批量处理，需要逐个执行。如需批量处理，可编写 shell 脚本循环调用。
