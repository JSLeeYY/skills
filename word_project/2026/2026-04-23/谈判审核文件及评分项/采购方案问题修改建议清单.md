# 《2026年度南京三方一体化数字信息平台优化提升项目开发采购方案》问题修改建议清单

说明：本清单依据当前版本采购方案正文整理，按“问题位置 + 存在问题 + 建议修改文本”方式编写，便于直接复制粘贴至 `docx` 中。

## 1. 评审办法与评分表逻辑不一致

问题位置：`五、采购谈判重点` 第 `3` 条

存在问题：
当前正文写的是“采用最低价法”，但现有评审资料已经采用“资格审查 + 定制开发评分 + 驻场运维评分 + 统一报价评分”的综合评审逻辑，二者口径不一致。

建议替换文本：

```text
3、谈判小组根据供应商的技术方案、驻场服务保障、履约能力、报价及商务响应情况，对供应商进行综合评审，并推荐候选成交供应商。资格审查合格后，按照定制开发评分、驻场运维评分、统一报价评分进行综合评分，按综合得分由高到低顺序推荐候选成交供应商，具体评分办法及权重以评审评分表为准。办公室依据谈判小组推荐的成交结果，编制谈判纪要，履行内部审批后确定成交供应商。
```

## 2. 谈判小组“单数”要求与成员名单不一致

问题位置：`五、采购谈判重点` 第 `1` 条，对应 `六、采购组成员`

存在问题：
正文写“`3人及以上的单数组成`”，但当前名单为 `4人`，存在前后不一致。

建议优先修改文本：

```text
1、谈判小组应当由综合办、数字信息部以及相关专业专家3人及以上组成。谈判小组应对供应商分别进行谈判。谈判中，谈判的任何一方不得透露与谈判有关的其他供应商的一切技术资料、价格或其他信息。
```

补充说明：
如果你坚持保留“单数”表述，则需在 `六、采购组成员` 中再补充 `1名成员`。

## 3. 采购依据年份较早，建议再确认口径

问题位置：`四、采购方式`

存在问题：
当前仍引用 `2024年8月20日` 采购申请表及 `2024年8月公司办公会纪要`。如该依据确为本项目沿用依据，可保留；如本项目已重新立项、列入 `2026年度预算`，建议同步更新。

建议替换模板文本：

```text
依据公司《非招标管理采购办法》，结合数字信息部于[请填写实际日期]提交的编号为[请填写实际编号]的采购申请文件，并按照公司[请填写实际会议时间]办公会/专题会议审议意见，采用谈判采购方式。
```

## 4. 数据分析需求表述仍偏“未收口”

问题位置：`3.1.3 数据与消息模块需求` 中 `（2）数据分析模块`

存在问题：
当前写法中“`具体分析维度需结合业务场景进一步细化`”说明需求尚未完全定稿，不利于正式采购文件使用。

建议替换文本：

```text
派单数据分析支持：在项目管理、任务派遣单等页面新增数据分析按钮，支持按项目经理、区域经理、项目编号、合同编号、制造厂、监造形式、派单状态、时间区间等维度查看业务数据，并支持图表展示与数据导出。
```

## 5. 开发管理条款中“可以”表述过软，建议改为“应”

问题位置：`3.5 开发管理需求`

存在问题：
当前多处使用“可以”“并可提供”等表述，约束力偏弱，不利于后续执行与验收。

建议整体替换为以下文本：

```text
为提高软件开发过程的质量和可靠性，减少缺陷，并确保项目按时按质完成，开发管理需求如下：

要求供应商派遣IT人员驻场办公，参与需求沟通、原型确认、设计、开发、测试、上线及问题整改等工作。

供应商提供的人员配置及合同签订后最快进场时间应满足项目开发进度要求。

供应商应安排专人参加需求沟通，所有开发需求形成需求原型，并与需求提出方进行确认，直至双方认可。

供应商应根据项目需要安排开发人员参加东软报表系统培训，并确保培训成果能够应用于本项目开发实施。

供应商应签署技术保密文件，并严格履行保密义务。项目全程产出的相关文档、代码、技术成果及知识产权归属甲方所有。

在系统上线运行时，供应商应提供《用户使用手册》，并提供3次以内的用户集中培训，不另行收费。

项目交付验收时，供应商应提交项目《概要设计说明书》《详细设计说明书》《数据库设计说明书》等相关技术资料文档，并可专项组织双方技术人员进行资料交接说明，维保期内负责答疑支持。
```

## 9. 经营分析系统名称中存在空格和写法不统一

问题位置：`3.4.8 系统架构与数据同步模块需求`

存在问题：
当前正文中多处出现 `经营管理分析 与 PECMS`、`经营管理分析 不单独登录`、`经营管理分析 中` 等写法，存在多余空格，不够规范。

建议替换文本：

```text
系统定位：经营管理分析与PECMS为两套独立系统，互不共库，基于前后端分离架构建设独立业务数据库。

登录与权限同步：经营管理分析不单独登录，由PECMS签发token进行鉴权；用户、角色、组织架构等基础数据由PECMS同步至经营管理分析。

基础数据同步：合同基础信息、项目组信息等基础台账支持全量加增量同步，或在PECMS新增合同时主动推送至经营管理分析。

动态数据同步：打卡记录、派单状态变更等动态执行数据通过消息或变更捕获机制写入经营管理分析，减少对PECMS主业务性能的影响。

数据只读规则：由PECMS和综合管理平台产生的原始执行数据在经营管理分析中仅可读不可回写；经营管理分析侧产生的收入纠正、审批历史、差旅工资等经营数据亦不反向写回PECMS。
```

## 10. 验收标准在付款条款中被提及，但尚未量化

问题位置：`七、主要商务内容` 第 `（5）` 条后，或付款条款后单列“验收要求”

存在问题：
当前付款条款提到了“稳定运行要求”“缺陷数量要求”，但正文未量化，后续执行时容易产生理解分歧。

建议新增文本：

```text
二、验收要求

各阶段交付内容应通过甲方组织的功能测试、联调测试及稳定性验证。每一阶段申请验收前，乙方应完成对应功能开发、测试整改、部署上线及问题复核工作，并提交测试报告、缺陷清单、整改闭环记录及甲方要求的其他验收资料。

各阶段验收时，重大缺陷应全部关闭，一般缺陷整改完成率原则上不低于95%；涉及消息提醒、数据同步、查询导出等功能的性能指标，应满足采购需求、测试用例及双方确认的验收标准。系统达到阶段性交付目标并连续稳定运行不少于[请填写天数]个工作日后，方可发起该阶段验收申请。
```

八、交付成果清单
