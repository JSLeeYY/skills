# 监造信息化系统甲方汇报页 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 产出一个仅包含单个 HTML 文件的甲方汇报页，完整覆盖 27 个原始业务模块、项目开发 SOP、软硬件入场与验收三大内容。

**Architecture:** 页面采用单文件实现，所有结构、样式、脚本、图形数据都内嵌在一个 HTML 中，不依赖额外 CSS/JS/图片/字体文件。页面内容先冻结为 4 份数据源：流程型模块、支撑型模块、SOP 阶段、软硬件对象；再由同一套渲染函数输出总览图、流程卡、能力卡、SOP 表、软硬件矩阵，保证口径统一、便于校验。

**Tech Stack:** HTML5, CSS3, Vanilla JavaScript, Inline SVG, 本地静态预览（无构建工具，无外部依赖）

## Implementation Constraints

- 只允许最终产出一个 HTML 页面，不新增本地 CSS、JS、图片、字体文件。
- 不允许 `<link rel="stylesheet">`、`<script src=...>`、外链字体、外链图片。
- 所有业务模块标题必须直接使用原始需求名称，且 27 个模块必须全覆盖，不多不少。
- SOP 必须固定为 5 列主信息：阶段 / 主责 / 配合 / 输出物 / Gate。
- 软硬件对象必须按 4 类展示：硬件设备 / 基础软件 / 安全与保障服务 / 网络接入方案。
- 应用系统必须出现在软硬件矩阵中，但并入“基础软件”展示，不单列第 5 类。
- 图形需投屏可读，不使用 Mermaid；统一采用内联 SVG 或纯 HTML 块图。
- Git 提交仅在用户明确要求时执行。
