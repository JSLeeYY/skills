# 运营与管理 (O&M) 平台整体需求规格说明书 (V10 最终落地方案版)

> **版本号**：V10.0 | **更新日期**：2026-03-03
> **编制说明**：本文档为 O&M 平台的最终执行标准。所有数据来源于原始 Excel 矩阵及最终版业务冲突修正问答记录。文档摒弃了原方案+补丁的冗余结构，将所有新确认的规则（如大屏业务、字典配置、数据来源、隐秘降耗及强约束字段）完全揉入具体的功能点中，作为直接的开发标准。

## 第一部分：架构设计

### 1.1 系统定位与边界（O&M vs PECMS）
- **平台级定位**：本系统（运营管理与经营分析平台）与 PECMS 平台为两个独立应用。
- **架构选型**：基于 RuoYi-Vue-Pro 前后端分离框架（包含其内置的可视化审批流引擎），并拥有独立的系统数据库。
- **用户体系与权限同步**：
  - O&M 系统维护自己的用户、角色与组织架构。
  - 依托于 PECMS 平台的单点登录（签发一致的 token）进行跳转访问。
  - 当在 PECMS 中进行用户角色或组织架构的**增删改**数据变更时，通过 Java 后端接口（API）的形式，将数据变同步推送到 O&M 系统的库表内，在 O&M 系统中保持数据一致。

### 1.2 核心数据隔离与同步机制
- **数据只读原则**：由 PECMS 原生业务产生的业务数据（如项目组人员名单、监理项目基础台账、计划时间、打卡时间、原始派单等），在 O&M 系统中**绝对只读**，严禁在 O&M 端逆向修改。
- **数据归属原则**：由 O&M 系统自身产生的数据（例如：收入纠正记录、自动补齐计算产值、O&M端的审批流历史记录、差旅工资等），全部**保存在 O&M 自身的数据库中**。
- **同步方案**：
  - **基础台账（如合同、人员组）**：可采取每天定时拉取（全量+增量）策略；或在 PECMS 新增节点时通过 API 主动推送。
  - **动态执行流（如打卡变动、派单状态演进）**：采用 Binlog 变更数据捕获工具（如 Canal、Debezium 或开源 MQ），让 O&M 监听消息进行异步落库，确保不耗费 PECMS 的直接并发性能。

## 第二部分：需求内容

### 1. 宏观层：高管运营管理大屏 (Executive Dashboard)
本部分由各子模块的数据底层直接提炼形成，为管理层提供全局透视面板。

#### 1.1 核心财务统览监控
- **全员/全案年度累计总合同金额**：实时抓取全库非终止状态之承揽合同总挂载金额。
- **当年累计确认产值总量**：以已入库且经确认排班折现的产值累加核定（总产值）。
- **累计已开票总额**：由财务入口校验之真实已开发票额度总和。
- **累计实际收款现金总额**：财务复核已划入公司账户底盘的明细总金额。
- **综合平均利润率及浮动**：依据动态成本推算结论生成加权利润占比，并附带展示同环比升跌指示。

#### 1.2 客户端（甲方）健康度漏斗图
- **立项基础主轴**：项目底层的委托方字段聚合。
- **四级漏斗梯度递推展示**：
  1. **【签约层】**：各甲方名下整体合同签约额总计
  2. **【产值层】**：已在系统确认的总产值
  3. **【开票层】**：已正常开票总金额
  4. **【实收层】**：到达实账户之收款兑付额
- **预警**：开票率或回款兑付差产生异常的不良收敛群，须标出警示名单。

#### 1.3 经营资金流趋势剪刀差警告折线图
- **横轴**：过去连续 12 个自然月。
- **双动线**：
  - **支出线（A线）**：累计真实产生已支付成本面（人员隐薪+差旅折合+分摊）。
  - **入账线（B线）**：累计其实收确报入账额。
- **剪刀差熔断填充**：当年月中发生**支出动线反超盖过入账动线时**（夹角倒挂），图形对应横跨区间自动标红/高亮告警区块，提示资金链失血或严重替垫情况。

#### 1.4 产能闲置率网格
- **核算基础**：排班表与花名册查重落盘，计算当朝处于非外派、未排班、纯闲置的挂印人数，折合未创造产值期间的公司日常定薪耗损总金，实施标红亮牌展示。

### 2. 合同台账管理
#### 2.1 角色与数据可见度权限
- **项目总监**：查看当前用户监管的项目下派单选用的合同号(CI编号)数据
- **项目经理**：查看分配给当前用户的合同号(CI编号)数据
- **总监代表**：查看当前用户负责的派单选用的合同号(CI编号)数据
- **合同负责人**：查看当前用户作为合同负责人的合同号(CI编号)数据
- **财务、领导层、管理员**：查看所有数据

#### 2.2 列表展示与高级筛选条件
**数据来源**：静态合同台账数据自 PECMS 同步。
- **列表展示字段**：监理编号、合同名称、设备名称、委托方、制造方、监造金额、预给号时间、项目负责人、合同签订时间、合同原件返回情况时间、合同起始日期、合同终止日期、委托方联系人、合同形式、ERP录入情况、合同特殊情况备注、供公司平台项目编号、供公司平台项目名称。
- **高级查询构造器（检索必须条件）**：合同台账不能仅照搬 PECMS 检索模块，需具备更高级的字段全拼图弹窗，包含：
  - 基础字段全录入（姓名、合同号等）；
  - 时间及数字金额字段均要附带双向箭头排序功能；
  - 支持按最终筛选条件导出 Excel（支持自选列表达式）。

#### 2.3 功能动作流（完成与终止）
- **完成判定准则**：
  - 只有在【实收金额】与【合同金额】数字完全一致（考虑系统后台可配置小数点的精准位数误差阈值）时，才露出完成强提示按钮。点击直接结束单据。
- **强制终止与取消终止**：
  - 点击取消终止弹出拦截框，**强校验需附记两大文本**：【取消终止主诉原因】及【预估重新挂起效期】。
  - 录入后提交流程走审批流（审批采用 RuoYi-Vue-Pro 引擎配置，审批节点配置化，界面展示流程序列）。

### 3. 项目收入管理
#### 3.1 角色权限与特殊规定
- **项目总监/项目经理的展示**：按辖区查看合同维度的数据。
- **【填报控制】**：该模块无总监代表参与角色，全部填报（如当月确认产值填报其他信息填报）由【合同负责人】执行。

#### 3.2 项目收入列表与高级筛查条件
- **列表字段**：监理编号、合同名称、委托方、合同负责人、合同类型、合同金额、总产值(元)、当月产值(元/月)、确认总产值、当月确认产值(元)、当月确认产值最新填报时间、已报收入、当月收入、开票状态、计划开票时间、未开票原因、最新开票时间、开票总金额(元)、最新收款时间、收款总金额(元)、备注。
- **特殊标识要求**：
  - 最新填报时间包含两个独立列：当月确认产值最近填时间及最近当月入数纠正时间；两者分别位于对应业务列后方，同屏幕并列展示。
  - 开票状态中若涉及人工合同时，以字典形式配置其固定展示语，默认读取字典展示标签：人工时定期据实结算。
- **列表支持排序**：凡是有关【金额】、【数字占比】以及【各种开票、回款等日期】表头，需全量支持正反排序。

#### 3.3 计算逻辑底层基准
- **总产值计算**：
  - 基于人工日：所有累积产生的每日（合单价 X 费时）相加（注：不平均分时间）。
  - 基于总价合包：总产值 = 已报收入。
- **当月确认产值填报校验与溢单审批**：
  - 无论是哪种报送法，操作人每次上报必须遵循一条坚决底线：(历史确认总产值 + 正在输入的这笔月额度)  签定的项目合同总金额。
  - **突破熔断机制（溢价报单）**：系统允许此数值越过封顶，但一旦越过，强行挂断其直接归入逻辑，**强制开启流程审查通道**进入超额审批流程；审批页需要拉取以下字段作佐料：【超额原因必填框表述】、【超额百分比比例数展示】、【是否有对应增补协议令关联勾认】、【证明底件附件传阅上传框】。
- **自动汇集补齐机制**：在原合同明确点击标记状态为已终结/完成时，如果系统比验此单仍属于未能满足合同总额定，立刻触发系统补齐，自动生成一笔系统补齐类型的历史充帐档位将其报结平额。

#### 3.4 当月收入纠正与其他信息填报
- **其他信息填报定义**：
  - 拆分为两个独立的动作按钮：
    - **开票信息填报**：仅限编辑【计划开票时间】【未开票原因】【备注】。
    - **回款信息填报**：仅限编辑【计划回款时间】【计划回款金额】【最新收款时间】【收款总金额】【备注】。
    (注：合同金额、月产值、开票状态、开票总和实银均为底层统计算数锁定锁格展示)
- **当月收入纠正（由财务或高参掌管）**：
  - 界面不需走审批。此操作实质指挪垫帐补正；
  - 点击展开必含如下：**【原欠/调来源头监理编号】**下拉必选项强筛锁定此调补资之来路归向，以追溯本由。且在纠正弹窗及后续记录中能清楚表明：从B户移交3万并给了此时A户。
  - 表头归算时，列表原大字段【已报收入】需要包容这些强行手动拨的平调数；悬停该位数字时，悬浮吐出起明细条：原已报X点，由某某单纠送X点，最后核实数为Z。

#### 3.5 全局历史溯源档案馆
- **单合同溯源**：点击列表右侧历史，可针对当前单项开启双切 Tab 查阅（填报查阅区 / 内部纠偏操作区），双边支持各种详致的多组合列名排序（支持大小排序）。
- **全局高管底牌池**：为平台级独立开立的一个超视距报表汇总大页面，无视具体的监理编号辖分限制，支持将公司过往数载全部涉及【单月确报历史】与【收纠更调】的历史全部并举出水面，使用强维度复合组合筛排搜检，直接支持高管盘查。

### 4. 执行管理
#### 4.1 数据拉取与变更指示
- **交互规则**：本菜单为独立查看界面（**完全禁止页面硬跳回 PECMS 老系统**），派单基本字段取值全由于 PECMS 传递存储库数据读取展示。
- **变更标星检测机制**：对于源头的系统变化（如源单取消了、源单换了外派人等），经营系统中设立专用的**【异常变更状态字段】**展示。如果历史追溯表中有动向发生查询命中，填注该变更概要提示文；若两边同安好，则落单填充为/。
- **时限预警超限与三色灯**：
  - **超期天数展示**：将天数明示悬挂（例：已延超时22日），并在整个单行的**这几个关联单元格做红漆染色**告醒。
  - **三色灯扩展（四色）**：可做系统字典配置。灰色(未起初)、蓝色(执行运转期)、绿色(完美关单)、加上**必须配置在超期时限点上触发染亮的【醒目超期预报警钟色：红/橙灯】**。

#### 4.2 非三方平台类底层强制拦截卡点 (技术文件校验)
- **判定机制**：对于不在 PECMS 等外部已设关卡内签验的外接合票数据源（经底层【是否走第三方监理系统】判否标志），其驻单需严守文卷质检；
- **必补缺报红警示**：以下技术报报件（共 7 条核对项）：
  【大纲是否已编制审核】、【细则是否已编制审核】、【风险评估报告风险等级】、【技术协议等依据性文件现场监理人员是否已拿到】、【监理工程师替换交接申请是否有】、【ITP是否已确认并发给委托方确认】、【预检会是否召开并有会议纪要】。
- **处理办法**：后台不生涩粗暴地堵挡报错弹框停止，对于发现为空项的数据表列采用标红重度标识，管理巡查人见此缺失，可在 O&M 提供的前台编辑补充单窗功能里面，逐项追溯询问补上或做解释更新落库保存（此操作权归属合同管理代表类成员）。

### 5. 开票明细与回款明细综合体系
本部分完全弃绝对接中化老 ERP 老口径，全面切向自主维护与导入管理。

#### 5.1 数据入口设定（新增与批量导入）
- **开票部分新增机制**：支持人工逐单据填写。需囊括：开票组织、开票客户、开票日期、发票号、币种、总数量、总金额、预计回款时间、合同负责人、监理编号(必须)、项目名称、凭证号、备注。点击保存只暂存（允许随意修删）；**一旦提交则立即固化生效（无须通过复杂的额外审批）**。
- **回款与凭单批量导入修改的审批**：不论哪头票据（包含各类压缩不失真的传图片与 PDF 证明底材集合件），若用外模执行了大规模导数，导入可以顺滑并库。但若是试图去动表篡改或消灭（删除删库 / 强修金额），**这类已确认动作将触及审批限制令**（流程结合 RuoYi-Vue 审核流发起申请核减审核）。

#### 5.2 大图层：回款穿透汇总联展（强管理界面要求）
- **行级跨合穿连**：回款这不单是笔看流水入帐的动作表，必须在此处将【各属合票】【该同胞派属的签金额度】的指标字段强拼合！比如这行显示回了1万元，同在一行必须展示该挂靠的监理编号下的【已开总票金额数】【累计认确认总产额】【待未回坏资金额度】这些同挂大财务关卡核定线字段，做直接同屏检算。
- **顶层报盘：多维大汇合汇总器页**：在明细录入界面之外，单开设立宏观综合分析页界面。要以业务人员骨干名头（例：张三的全部案表）、不同监理承源类为主纬度切分。将他们麾下这段区间带动的各合同名下的票开及血已回现本打透合并汇总并加底算和查核业绩能力用报表给上端审。

### 7. 动态成本核算管理
本部分主要对隐性薪耗与杂旅进行精密细拆，坚决把这部分耗损扣出真假利润，以及防止乱排班造成虚高复利。

#### 7.1 工资定金极密匿踪禁区
- **真数据遮断红线**：只要是由财局人政上递并录填的职干每月基固定粮薪（人手成花销底价），所有非系统直接执行核心算式的外露网格及报明界面（例如点击人员的差本或其详细属性窗时），**一律进行深度密防隐藏及星号完全加涂绝屏蔽（甚至杜绝所谓的特许鼠标悬停破译展阅功能）**；它只在这库心暗转参与减耗化合大均式公式运算，页面能表列显示的唯有一栏已汇总打碎不可溯回名账的具体【折消耗列总和数表面值】。

#### 7.2 杂乱差旅报报调切法与项目成本切蛋糕算法
- **复派平折法则（算成本不平均算产值）**：此在精盘项目明帐中：如果某同单内当事劳员同期横担多条发令出任于多案合同源下；那属于他在案的产生时基底成本算式必须行：**把此同员当日给工金原合金额 / 这个日子里总兼挂的任务签大案数基数比例平摊拆均减除法（即这块这几日同身在多标时分着吃成本价）！**
  - **注：**而上段对应的他的【工作上产值】就不去摊去搞均了，该算给哪个挂了牌的就是单挂出总头表数，不可混。 
- **差旅等耗值切分支持双手动规矩调整**：针对这类乱杂入数（如导入了一笔统汇差报费：机宿联结票），由于分配在不同编号项目无法机分准确，由对应人员进行窗联分配微调：
  - 可以输入按工日数等额度由除法平定分给各个CI项目口（天数切法定法）。
  - 或者干脆允许手造填录：将出票那包数字进行自敲平分的数字，录分砸派回所挂各合同额度单上入库当消耗，完成单合核计核价。

### 8. 利润管理与数据报表综合面
#### 8.1 阶梯阀值配比报警配色与持续警告逻辑法
- **颜色告警的非硬核固化要求**：放弃固守正负 0 作为唯一标识的标准；而是提供字典调阀，譬如对系统设控利润率：当算得留存百分比在【0 - 3%】夹缝狭线间，即刻将其挂牌**【橙色或黄色警鸣色】做极位薄利底报警**；小于 0 底大漏跌破再挂【全格深红字大示灾】区，并随正常赢利率高转显示【绿意达标大牌】等。全支持系统总管界表进行这几个切线点的重调及重设色块选择。
- **超降线的疯狂警示机铃**：凡当上述核单坠挂进了黄色或红标时机警点时。不是只敲这响一下完事。在未做更调前，这是一个循环连带大警告提示，必须定时段（此间隔段也可进管理词典变置更改）在平台中心敲弹传书，直到这个涉险的项目所有承局涉事人及经案负责人乃至相关联全挂出名单均已知该核单在每个具体计算环节中哪个数字出了恶漏引发超线警文！

#### 8.2 宏观全局图表与组合展现
- **图形定制能力**：图表默认生成包括各种柱分及大折线长拉图，供挑选并留有自定义选项。可提供直接点击切换及同版块表联动的特性（禁止系统外人员/无大权限人员越位编挂和改变内部报核生成法则限制）。
- **大局与单挂组合面**：分析面板不能只单独钻进某一根独独的承同标编号内算来显走势；必须是宏界设计：页面在半面框住明表名录条文的这基础上，下方或是提供另一个超链接统集总画专集页报，可在此间由总干览尽各个多项包挂的纵横合并大总利核成并拢势盘展示长表；以成能容多且全局览望全系宏大之貌。
