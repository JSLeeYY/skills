# 代码安全检查快速清单

## 修改前必查项

### ✓ 基础检查
- [ ] 明确要修改的代码元素（函数/类/样式/变量）
- [ ] 使用 Grep 搜索所有引用位置
- [ ] 记录引用数量和位置

### ✓ 影响分析
- [ ] 分析每个引用位置的使用方式
- [ ] 识别直接影响和间接影响
- [ ] 标注高/中/低风险区域

### ✓ 复用检查（如适用）
- [ ] 理解原代码的具体用途和上下文
- [ ] 评估新用途与原用途的兼容性
- [ ] 确认复用不会影响原位置功能

### ✓ 修改方案
- [ ] 制定详细的修改步骤
- [ ] 准备验证方法
- [ ] 准备回滚方案

### ✓ 执行验证
- [ ] 修改代码
- [ ] 验证修改位置功能正常
- [ ] 验证所有引用位置功能正常
- [ ] 运行相关测试
- [ ] 检查样式和 UI

## 常见搜索模式

### 搜索函数引用
```
Grep: pattern="functionName\\(", output_mode="content"
```

### 搜索类/组件引用
```
Grep: pattern="(import|from).*ComponentName", output_mode="content"
```

### 搜索 CSS 类名
```
Grep: pattern='className="[^"]*targetClass', glob="**/*.{jsx,tsx,html}", output_mode="content"
```

### 搜索变量赋值和读取
```
Grep: pattern="variableName", output_mode="content"
```

## 风险等级判断

### 🔴 高风险（需要特别谨慎）
- 引用位置 > 10 个
- 跨多个模块使用
- 核心业务逻辑
- 全局样式或配置
- API 接口变更

### 🟡 中风险（需要仔细验证）
- 引用位置 3-10 个
- 单模块内多处使用
- 共享组件或工具函数
- 局部样式影响多个元素

### 🟢 低风险（常规验证）
- 引用位置 < 3 个
- 局部作用域
- 新增代码无依赖
- 私有函数或样式

## 快速决策树

```
要修改代码？
  ↓
搜索引用 (Grep)
  ↓
引用数量？
  ├─ 0个 → 可以安全删除
  ├─ 1-2个 → 检查这些位置 → 低风险修改
  ├─ 3-10个 → 详细分析影响 → 中风险修改
  └─ >10个 → 全面评估 → 高风险修改
       ↓
  制定分步方案
       ↓
  逐步修改+验证
```

## 记住

- **永远先搜索，再修改**
- **不确定时，选择保守方案**
- **大改动拆分为小步骤**
- **每步都要验证**
