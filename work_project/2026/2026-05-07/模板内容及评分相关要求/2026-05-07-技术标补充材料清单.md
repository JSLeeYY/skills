# 技术标补充材料清单

---

## 一、这份清单的编制口径

### 1.1 这次采用的总原则

本清单以招标文件整体结构为主线，不把技术标孤立出来看。技术标只是整份投标文件中的一部分，必须同时满足：

1. 第一章招标公告中的项目范围、交货期、交货地点、质量标准、资格条件、递交方式。
2. 第二章投标人须知中的投标文件组成、保密要求、偏差规则、技术支持资料规则、投标保证金、纸电版一致性、排版装订要求。
3. 第三章评标办法中的初步评审、资格评审、响应性评审和技术评分标准。
4. 第五章供货要求中的功能范围、架构要求、安全要求、性能要求、硬件软件清单、交付资料要求。
5. 第六章投标文件格式中的正式目录、索引表、偏差表、资格表、类似项目表和技术文件栏目。

### 1.2 招标文件内部解释顺序

根据招标文件第二章第 `2.1` 节正文，文件前后不一致时，解释优先顺序为：

1. 招标文件澄清、修改
2. 招标公告
3. 投标人须知前附表
4. 投标人须知正文
5. 评标办法前附表
6. 评标办法正文
7. 供货要求
8. 投标文件格式

这意味着：

- 不能只盯第三章评分表写技术标。
- 不能只照第六章模板机械填空。
- 也不能只把第五章功能需求抄一遍。
- 必须先尊重第一章、第二章的基础约束，再把第三章、第五章、第六章落成可评审、可核验、可归档的投标文件。

### 1.3 本清单中三类材料的定义

为了避免再次混淆，本清单把材料分成三类：

1. `招标文件明示要求`
   来自招标文件正文、前附表、模板、供货要求、交付资料清单中已经写明必须提供或必须出现的材料。
2. `评分支撑材料`
   招标文件虽然未单独列成“必须提交附件名称”，但第三章评分标准和第五章技术要求已经明确要求有证据支撑，否则失分或无法证明响应。
3. `风险补充材料`
   用于解决招标文件内部口径冲突、外部附件引用内容未落地、后续合同履约边界不清、技术标承诺前后打架等风险，不属于“凭空发挥”，而是为正式投标落地服务。

## 二、招标文件整体框架与技术标所在位置

### 2.1 整份招标文件的主结构

1. `第一章 招标公告`
2. `第二章 投标人须知`
3. `第三章 评标办法`
4. `第四章 合同条款及格式`
5. `第五章 供货要求`
6. `第六章 投标文件格式`

### 2.2 技术标并不是“单独的一本技术方案”

本项目技术标相关内容，实际分散在以下位置：

1. 第二章 `3.1.1` 规定投标文件组成，其中技术相关核心栏目为：
   - `（11）投标设备技术性能指标的详细描述`
   - `（12）技术支持资料`
   - `（13）技术服务和质保期相关服务计划`
   - `（14）其他资料`
2. 第三章附件 1、附件 2、附件 3 决定了：
   - 初步评审不能掉项
   - 资格审查不能虚假
   - 响应性评审不能偏离实质性要求
   - 技术评分必须有证据链
3. 第五章决定了：
   - 你到底要响应什么功能、什么架构、什么软硬件、什么安全与性能、什么交付资料
4. 第六章决定了：
   - 你最终交出去的材料必须长成什么结构、放在什么栏目、怎么给评委建立索引

### 2.3 第四章的特别说明

当前 `docx` 中第四章只有一句引用：

`详见附件【非密】20250929-14-02-【合同模板】- 系统`

招标文件主文里第四章只保留了这一句引用，但该合同模板现已取得，且其中已经形成了必须反写到技术标中的约束：

1. `工期与阶段里程碑`
   合同模板明确：签约后 `2` 个月完成详细设计评审，实施部署 `4` 个月，平台测试 `2` 个月，试运行 `5` 个月。
2. `技术资料与交付文件`
   技术资料、提交文件清单、项目进度计划、源地验收大纲、调试大纲、随机资料、纸电版要求、文件命名和版本管理均受附件 `1《技术协议》`、附件 `3《文件编制要求、清单及时间表》`约束。
3. `验收与质保`
   安装完成后先做质量初验收；完成安装调试并最终验收合格后进入质保期；质量保证期为通过性能验收试验之日起 `24` 个月。
4. `知识产权与保密`
   买方提供资料及其衍生改进归买方；卖方交付的产品和文件资料不得侵权；合同执行过程中不得擅自拍摄现场照片或对外宣传合作关系。
5. `付款与违约`
   交货款、调试验收款、质保金与交货、验收、质保评定直接挂钩；技术服务失误、侵权、泄密、性能不达标和延误工期都会触发违约责任和扣款。

## 五、第三章评分与第五章供货要求对应出的技术标核心证据

### 5.1 第三章技术评分的六个核心项

1. `系统功能匹配度 0-10`
2. `技术方案可行性 0-15`
3. `项目实施能力 0-8`
4. `系统设计要求及成熟度 0-6`
5. `进度与业绩演示 0-6`
6. `售后服务及运维 0-5`

### 5.2 第五章供货要求中明确需要被技术标覆盖的内容

1. 功能范围：监造体系管理、质量计划、巡检、抽查复验、监造记录、完工管理、放行、趋势分析、追溯、风险预警、可视化、二维码、电子签名、培训授权等
2. 总体目标：标准化、业务协同、问题闭环、数据分析、追溯支撑
3. 系统设计要求：安全性、成熟性、易用性、扩展性、可维护性
4. 技术要求：B/S 架构、移动端支持、统一登录、模块化、接口集成、部署要求
5. 功能子模块：二维码、图文识别、视频远程识别、培训与考试、AI 基础识别等
6. 安全要求：权限、口令策略、日志分析、加密、防火墙/VPN、漏洞检测、等保测评
7. 性能要求：`100` 用户同时访问、CPU 峰值、内存峰值、负载均衡、集群、`7x24`
8. 软硬件清单：客户端、国产操作系统、高性能数据库、第三方安全检测、服务器资源等
9. 交付资料：源代码、需求说明书、设计方案、测试报告、试运行报告、验收报告、培训资料等
