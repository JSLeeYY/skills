### 12.2 项目理解与需求分析

#### 12.2.1 项目目标理解

本项目不是单一功能软件采购，而是围绕监造业务全过程，建设一套可落地、可追溯、可分析、可留痕、可扩展的监造管理系统。目标可以归纳为五个层面：

1. 建立统一的监造业务平台，承接监造任务、策划、过程监督、问题处理、验收和放行。
2. 建立标准化的质量计划与见证管理体系，把监造依据、见证点、问题单据和记录表单结构化。
3. 建立面向采购物项的全过程追溯体系，实现原材料和设备两个模块的逻辑隔离、数据归集和链路联查。
4. 建立质量问题和趋势分析机制，把业务数据沉淀为管理视图和风险预警能力。
5. 建立可持续运行的国产化技术底座，满足数据中心部署、安全合规、运维监控和后续扩展要求。

#### 12.2.2 项目关键难点理解

结合招标文件内容，我方认为本项目真正的难点不是开发页面数量，而是以下六项：

1. 业务链条长：覆盖任务、策划、见证、问题、验收、放行、追溯、分析等全过程。
2. 过程留痕要求高：需要实现表单、附件、影像、审批、日志全链留痕。
3. 国产化环境约束明显：服务器、操作系统、数据库和浏览器均有兼容要求。
4. 安全要求高：涉及 VPN、漏洞检测、等级保护、保密自监管和权限分级。
5. 交付物要求完整：系统之外还要交付源码、计划、设计、说明书、测试报告、培训资料等。
6. 招标文件口径存在冲突：工期、试运行周期和部分安全/部署条款需要靠合理方案消化。

### 12.5 系统功能匹配度（10分）

#### 12.5.1 响应结论

#### 12.5.2 总体业务架构

系统整体采用“一平台、两专项、四支撑、全留痕”的业务架构：

1. 一平台：统一门户、统一认证、统一权限、统一消息、统一日志、统一查询。
2. 两专项：原材料采购全流程追溯模块、设备采购全流程追溯模块。
3. 四支撑：流程引擎支撑、文件与影像支撑、统计分析支撑、接口交换支撑。
4. 全留痕：所有关键业务动作、附件上传、审批意见、状态变化、质量闭环均形成留痕。

#### 12.5.3 两个逻辑隔离数据接入模块设计

针对招标文件特别提出的两个标准化数据接入模块，我方按以下方式实现：

1. 在同一平台内按模块域进行逻辑隔离，分别管理原材料与设备的数据模型、表单模板、流程实例和统计口径。
2. 采用统一的用户身份体系和权限框架，但不同模块的数据访问范围独立配置，避免跨模块误操作。
3. 两个模块共享统一接口标准、统一编码规则和统一日志审计能力，降低后续扩展和运维成本。
4. 模块间如需交叉查询，只提供经过授权的联查视图，不直接共享底层业务操作权限。

#### 12.5.4 原材料采购全流程追溯模块

本模块重点解决原材料制造过程节点、关键工序见证、完工文件、源地验收和发货数据的在线采集与链路追溯，具体实现如下：

2. 对制造过程关键工序设置见证点、记录模板、上传要求和判定标准。
3. 对原材料完工文件、源地验收资料、发货清单和二维码标识进行统一挂接。
4. 支持按物项编号、合同编号、制造厂、批次和时间维度反向追溯。

#### 12.5.5 设备采购全流程追溯模块

本模块重点解决设备制造过程节点、关键工序见证、出厂检验记录及源地验收数据的规范化归集，具体实现如下：

1. 建立设备对象、部组件对象和质控点对象之间的关联关系。
2. 对制造、见证、出厂检验、整改、验收和放行形成贯通链路。
3. 所有设备档案均支持结构化数据和附件双重留存。
4. 支持设备质量问题与追溯信息联查，为后续质量分析和风险识别提供依据。

#### 12.5.6 体系文件管理

体系文件管理不是单纯的文档上传功能，而是监造依据管理底座。系统按“公司管理文件、第三方监造文件、供应商规程、质量依据文件、标准规范文件”分类建库，实现：

3. 只读、下载、引用、审批等权限分级。

#### 12.5.7 任务分配管理

任务分配管理的核心不是给人分活，而是把采购包和监造责任闭环到人。系统实现：

#### 12.6.2 总体技术路线

3. 接口失败不影响本地业务草稿保存。

#### 12.6.8 安全方案设计

##### 12.6.8.1 总体安全思路

本项目安全不单独做一个“安全模块”，而是把安全能力嵌入账号体系、权限体系、数据体系、日志体系和运维体系中。具体包括：

1. 账号安全
2. 权限分级
3. 数据加密
4. 日志审计
5. 漏洞整改
6. 等保配合

##### 12.6.8.2 账号与认证安全

1. 账号采用统一用户管理。
2. 口令策略支持长度、复杂度、有效期和失效提醒。
3. 支持登录超时控制、锁定机制和排他性登录管理。

##### 12.6.8.3 权限分级控制

1. 组织、角色、岗位、业务范围四层结合授权。
2. 功能、按钮、字段、数据范围四级控制。
3. 两个追溯模块数据访问范围独立控制。
4. 管理看板和统计数据按管理范围可见。

##### 12.6.8.4 数据传输与存储安全

1. 重要接口采用加密传输。
2. 敏感字段进行存储保护。
3. 影像和附件访问采用权限校验和下载控制。
4. 关键表单和单据支持防篡改归档。

##### 12.6.8.5 日志审计与安全追溯

1. 记录登录、登出、审批、导出、删除、关闭、放行等关键动作。
2. 接口调用和异常信息单独记录。
3. 日志按安全、业务、运维三类管理。

##### 12.6.8.6 等保与漏洞整改配合

1. 上线前配合完成等级保护测评。
2. 配合第三方漏洞扫描和代码安全检测。
3. 对测评与扫描发现的问题建立整改清单、责任人和关闭记录。

#### 12.6.9 性能与可靠性方案

##### 12.6.9.1 并发与响应保障

1. 采用分层架构减少无效跨层调用。
2. 高频查询建立索引和缓存策略。
3. 复杂统计报表采用异步计算或离线汇总机制。
4. 大文件上传采用分段上传和后台处理机制。

##### 12.6.9.2 高可用与容错设计

1. 应用服务支持多实例部署。
2. 中间件和数据库支持主备或集群机制。
3. 文件存储支持备份与冗余。
4. 关键任务失败支持重试和人工补偿。

#### 12.6.10 运维监控方案

1. 监控 CPU、内存、磁盘、服务进程、队列、接口、数据库连接等运行指标。
2. 对登录异常、任务失败、接口失败、空间不足等场景形成告警。
3. 提供日常巡检清单、版本发布清单和应急回退清单。
4. 重要问题形成问题单和整改闭环。

#### 12.6.11 兼容性适配方案

1. 服务器环境适配海光 CPU。
2. 操作系统适配银河麒麟 `V10`。
3. 浏览器兼容奇安信、火狐、Chromium 内核主流浏览器。
4. 预留移动端轻量访问和后续独立 APP 扩展能力。
