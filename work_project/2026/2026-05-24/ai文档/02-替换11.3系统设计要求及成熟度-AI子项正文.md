# 11.3系统设计要求及成熟度-AI基础识别功能响应正文

## 11.3.2.1 AI基础识别功能成熟度说明

针对评分标准中“AI基础识别功能：可以进行智能文档识别，具备基础的信息智能查阅；同时，具备资料查询辅助功能，方便监造人员进行知识查询”的要求，我司已围绕监造资料处理、技术协议识别、质量问题汇总、资料检索、历史案例查阅和过程文稿生成等场景开展了AI能力建设和工作流验证。

我司AI能力不是停留在单纯问答或概念演示层面，而是已经形成以本地部署DIFY为编排平台、以本地部署国产化模型为推理能力、以本地文档解析服务和本地知识库为支撑的私有化AI处理方案。模型能力可采用本地部署的千问模型，也可根据甲方环境和国产化适配要求切换为本地部署的DeepSeek模型。文档解析、知识库检索、文件处理、统计分析、报告生成和运行日志均可在本地环境内完成，满足项目资料不出域、模型推理可控、过程结果可追溯的要求。

本节围绕“我司已经实现的内容”和“面向本项目功能定制的实现方案”两部分进行说明，便于评标专家从已完成能力、可证明材料和本项目落地路径三个层面核验AI基础识别功能的成熟度。

### 二、面向本项目AI基础识别功能的定制实现方案

#### 1. 建设目标与总体定位

本项目AI基础识别功能建设目标，是在不改变监造业务审批责任、不替代专业质量判断、不绕开人工复核的前提下，为监造人员提供“资料识别更快、关键信息查阅更准、历史资料复用更方便、质量问题汇总更高效、过程文稿形成更规范”的辅助能力。该功能重点服务于技术协议识别、扫描件/PDF资料解析、标准资料查询、历史案例检索、质量问题汇总、监理大纲辅助生成和资料归档字段提取等场景。

本项目拟采用“本地DIFY编排平台 + 本地国产化大模型 + 本地文档解析服务 + 本地知识库 + 人工复核闭环”的方式建设AI基础识别能力。DIFY负责工作流编排、文件接收、模型调用、知识检索、节点流转、结果输出和运行留痕；本地部署的千问模型或DeepSeek模型负责文档理解、字段抽取、表头识别、问答生成、统计分析和结果校验；本地文档解析服务负责PDF、Word、Excel、扫描件、图片附件和多文件资料的文本提取及结构化转换；本地知识库负责法规标准、技术规范、历史案例、培训资料、质量问题记录和项目经验资料的检索。

本项目AI基础识别功能的整体处理链路如下：

监造人员上传资料或发起查询 -> 本地DIFY工作流接收输入 -> 文档解析服务提取文本、表格和版式结构 -> 本地国产化模型识别字段含义、业务对象和统计口径 -> 本地知识库检索相关标准、案例和历史资料 -> 系统生成结构化结果、查询答案、统计图表或报告草稿 -> 人工复核、修订和确认 -> 进入正式业务链或资料归档。

通过上述方式，AI基础识别功能既能响应评分标准中“智能文档识别、基础信息智能查阅、资料查询辅助、知识查询”的要求，也能与本项目已有的数据信息资源库、培训与考试模块、资料归档模块、质量问题处理模块、统计分析模块形成联动。

#### 2. 本地部署与国产化技术路线

本项目AI能力采用本地化、私有化部署方式实施，避免项目资料、质量问题台账、历史案例和培训资料经由公网外部模型服务处理。部署方案建议包括以下内容：

1. DIFY平台部署在甲方认可的本地服务器、内网服务器或专有云环境中，用于AI应用编排、工作流配置、运行调度、用户入口和结果输出。
2. 大语言模型采用本地部署的国产化模型，可优先选用千问模型，也可根据甲方技术路线和运行环境选用DeepSeek模型。
3. 文档解析服务本地部署，用于处理PDF文本提取、扫描件OCR、Word正文读取、Excel表格解析、图片文字识别和Markdown结构化转换。
4. 知识库和向量索引部署在本地环境中，法规标准、技术规范、历史案例、质量问题记录、培训资料和项目经验资料均在本地处理和存储。
5. 文件存储、运行日志、模型调用记录、结果输出和人工复核记录均保留在本地系统中，满足数据安全、审计留痕和后续追溯要求。

本地部署后，系统运行边界清晰，上传资料、模型推理、知识检索、报告生成和结果确认均在甲方认可环境内完成。对于后续国产化适配，可根据甲方服务器、操作系统、数据库、中间件和模型部署环境进行调整，保证AI能力可部署、可运维、可扩展。

#### 3. DIFY工作流总体设计

本项目AI基础识别功能拟在DIFY中配置多条业务工作流，并根据业务入口进行调用。工作流设计不采用单一问答方式，而是按监造业务场景拆分为文档识别、资料查阅、知识查询、质量问题分析和过程文稿生成等能力链。

主要工作流建议如下：

| 工作流名称 | 主要输入 | 主要处理内容 | 主要输出 |
| --- | --- | --- | --- |
| 智能文档识别工作流 | PDF、Word、扫描件、图片附件 | 文本提取、OCR识别、关键字段抽取、关键页定位 | 字段清单、来源片段、结构化JSON |
| 技术协议分析工作流 | 技术协议、图纸说明、数据表 | 设备信息识别、材质参数抽取、检试验要求提取、风险点识别 | 设备参数表、风险要点、监造关注项 |
| 资料查询与知识问答工作流 | 用户问题、关键词、资料类型 | 知识库检索、相似案例召回、标准条款定位、答案生成 | 问答结果、引用来源、相关资料 |
| 质量问题汇总分析工作流 | Excel问题清单、整改台账、多文件资料 | 表头识别、字段映射、统计分析、图表生成、报告生成 | 质量问题分析报告、统计图表、明细清单 |
| 监理大纲辅助生成工作流 | 技术协议PDF、项目提示信息、标准参考 | 文档画像、参数抽取、JSON校验、Word模板回填 | 监理大纲Word初稿 |
| 资料归档辅助工作流 | 待归档资料、项目标签、业务阶段 | 分类建议、关键字段提取、一致性检查 | 归档分类建议、字段补全建议 |

上述工作流可按项目阶段逐步启用。初期优先实现智能文档识别、资料查询辅助和质量问题分析，随后扩展监理大纲生成、资料归档辅助和知识问答能力。

#### 4. 智能文档识别流程设计

智能文档识别流程用于处理本项目常见的PDF、扫描件、Word、Excel、图片附件和多文件资料。流程设计建议如下：

1. 输入接收。用户在系统中上传技术协议、制造资料、检验记录、质量问题清单、整改台账、扫描件或图片附件，并选择资料类型、所属项目、业务阶段和处理目的。
2. 文件预处理。系统识别文件格式、文件大小、页数、表格数量、是否扫描件、是否包含图片或附件，并根据文件类型选择解析方式。
3. 文本提取。对可读PDF、Word和Excel直接提取正文、表格和字段；对扫描件和图片附件调用OCR识别；对结构复杂PDF调用本地解析服务转换为Markdown或可处理文本。
4. 关键内容定位。对长篇资料先定位关键页、关键表格和关键段落，优先识别项目名称、设备名称、位号、主体材质、规格型号、数量、标准依据、检试验要求、质量问题描述和整改状态。
5. 字段抽取。调用本地部署模型抽取业务字段，形成结构化字段清单，并保留来源文件、来源页码、来源行列或来源片段。
6. 结果校验。系统对抽取结果进行完整性、格式一致性和字段逻辑校验。例如设备名称不能为空，关闭状态应与整改结论匹配，问题类别应落入预设类别范围。
7. 人工复核。业务人员查看系统识别结果，对关键字段进行确认、修改或补充。
8. 结果输出。经确认后的字段可用于资料归档、统计分析、问题闭环、报告生成或后续知识库沉淀。

通过该流程，系统可将分散在不同格式文件中的业务信息转化为可检索、可校验、可复用的数据，减少人工查找和重复录入工作。

#### 5. 技术协议和监造资料识别方案

针对本项目监造业务中常见的技术协议、设备资料、图纸说明、数据表和制造文件，系统将重点识别以下内容：

1. 项目基础信息：项目名称、合同名称、装置名称、采购包名称、业主单位、设计单位、制造单位、供应商名称。
2. 设备基础信息：设备名称、设备位号、设备类型、数量、规格型号、设计寿命、设计压力、设计温度等。
3. 材料与结构信息：主体材质、换热管材质、管板材质、壳程/管程材质、焊接材料、特殊材料要求等。
4. 制造与检验要求：焊接、无损检测、热处理、压力试验、气密试验、氦检漏、酸洗钝化、防腐包装、出厂资料等。
5. 监造控制要点：H点、W点、R点、S点，重点见证事项，需提交的质量证明文件和过程记录。
6. 风险关注点：材料错用、焊接缺陷、无损检测比例不足、压力试验记录缺失、资料不完整、包装防护不到位等。

系统识别上述内容后，可形成设备参数清单、监造关注点清单、检试验要求清单和资料提交要求清单。上述清单可作为监造策划、监理大纲编制、质量计划审查和资料归档的基础输入。

#### 6. 质量问题汇总分析方案

针对本项目质量问题处理和整改闭环场景，系统将结合已实现的质量问题分析报告工作流，建设质量问题汇总分析能力。该能力面向质量问题清单、整改台账、问题闭环记录、供应商问题记录等Excel或多文件资料，重点实现以下内容：

1. 表头识别。系统自动识别Excel或表格中的供应商、问题描述、问题类别、责任单位、整改要求、关闭状态、计划完成时间、实际完成时间、验证结果等字段。
2. 字段映射。对不同模板、不同命名方式的字段进行统一映射。例如“供应商名称”“厂家”“责任供方”可映射为供应商字段，“状态”“关闭情况”“是否关闭”可映射为关闭状态字段。
3. 数据清洗。对空值、重复记录、格式不一致、状态写法不一致、供应商名称不一致等情况进行整理，并标记需要人工确认的数据。
4. 分类统计。按供应商、问题类别、关闭状态、专业类别、整改阶段等维度进行统计，形成问题数量和占比。
5. 图表生成。生成供应商分布饼图、问题分类柱状图、关闭状态饼图等可视化结果。
6. 明细输出。输出质量问题明细清单，保留问题序号、供应商、问题描述、类别、状态、整改要求和备注信息。
7. 结论建议。根据统计结果辅助形成重点供应商管控建议、主要问题类别整改建议、质量证明文件审核建议、未关闭问题跟踪建议。
8. 报告生成。将统计结果、图表、明细和建议整合为Markdown报告，并导出DOCX分析报告草稿。

该功能可用于项目质量例会、阶段质量复盘、供应商质量表现评价、整改闭环跟踪和甲方质量管理汇报。系统输出仍需人工复核，尤其是问题类别、责任单位、整改建议和关闭状态等涉及管理判断的内容。

#### 7. 基础信息智能查阅方案

基础信息智能查阅能力用于解决监造人员“想查某个信息但不知道在哪份资料、哪一页、哪个表格里”的问题。系统将围绕项目资料和知识库提供查询入口，支持按关键词、字段条件和自然语言问题进行查阅。

查询方式包括：

1. 按项目查询。输入项目名称或项目编号，查看该项目相关技术协议、监理大纲、质量问题清单、检试验要求和资料归档情况。
2. 按设备查询。输入设备名称、位号或设备类型，查看设备参数、材质信息、检试验要求、风险关注点和历史相似案例。
3. 按供应商查询。输入供应商名称，查看该供应商质量问题数量、主要问题类别、关闭情况、历史表现和关联资料。
4. 按问题类别查询。输入外观、尺寸、材料、焊接、无损检测、过程资料、试验等类别，查看相关问题明细和整改建议。
5. 按标准或条款查询。输入标准编号、检验项目或质量要求，查看相关标准条款、适用资料和引用来源。
6. 按自然语言查询。输入“某类换热器重点监造风险有哪些”“当前未关闭质量问题有哪些”“供应商问题主要集中在哪些方面”等问题，系统返回摘要结果和来源依据。

查询结果建议包括直接答案、来源资料、来源段落或表格、关联案例、相关附件和人工复核提示。对涉及关键业务结论的内容，系统不直接给出最终审批意见，而是提供辅助查阅结果。

#### 8. 资料查询辅助和知识库建设方案

本项目资料查询辅助功能将依托本地知识库建设。知识库不是简单文件堆放，而是围绕监造业务对象、资料类型和使用场景进行组织，使监造人员能够快速检索、复用和核验资料。

知识库建议建设以下内容：

1. 法规标准库。包括国家标准、行业标准、企业制度、监造管理文件、检验检测相关规范等。
2. 技术规范库。包括技术协议、设备数据表、图纸说明、制造技术要求、检试验计划等。
3. 历史案例库。包括历史监造大纲、质量问题案例、整改闭环案例、供应商质量表现、典型风险点等。
4. 培训资料库。包括系统操作手册、监造业务培训资料、质量问题处理培训资料、标准宣贯材料等。
5. 项目经验库。包括阶段总结、复盘报告、常见问题问答、资料归档经验、项目实施经验等。

知识库资料应按项目、设备、供应商、资料类型、业务阶段、专业类别、问题类别等维度设置元数据标签。系统检索时可结合语义检索、关键词检索、元数据过滤和人工收藏结果，提高查询准确性。

知识库更新机制建议如下：

1. 项目资料经人工确认后进入知识库。
2. 质量问题关闭后形成案例沉淀。
3. 培训资料、操作手册和常见问题定期更新。
4. AI识别结果经人工复核后可作为结构化知识补充。
5. 对过期标准、作废资料和重复资料设置维护机制。

通过上述设计，系统可将项目实施过程中的资料和经验逐步沉淀为可查询、可复用、可培训的知识资产。

#### 9. 知识查询和问答辅助方案

面向监造人员日常知识查询需求，系统将在DIFY中配置知识问答工作流。用户提出问题后，系统先判断问题类型，再检索本地知识库和项目资料，最后由本地部署模型基于检索结果生成回答。

知识问答处理步骤如下：

1. 用户输入问题，例如标准查询、资料查询、案例查询、设备参数查询、质量问题查询或系统操作查询。
2. 系统识别问题类型和查询意图，判断应检索标准库、案例库、项目资料库、质量问题库还是培训资料库。
3. 系统检索相关资料，并根据项目、设备、供应商、业务阶段等条件过滤结果。
4. 系统对检索片段进行归并、去重和排序。
5. 本地模型生成问答结果，同时保留引用来源。
6. 用户查看结果后，可进一步打开来源资料、复制引用内容或发起补充查询。

典型问答示例包括：

1. “换热器管板堆焊监造时应重点关注哪些风险。”
2. “某供应商未关闭质量问题有哪些。”
3. “外观类质量问题整改时应重点核查哪些资料。”
4. “类似项目监理大纲中如何设置压力试验见证点。”
5. “材料质量证明文件审核应检查哪些要素。”

系统回答应坚持引用依据优先，避免无来源扩展。对没有检索到明确依据的问题，系统应提示“未检索到明确资料依据，建议人工核查相关文件”，避免未经核实的内容进入正式业务判断。

#### 10. 过程文稿和报告辅助生成方案

在文档识别、字段抽取和知识检索基础上，系统可辅助生成部分过程性文稿。该能力主要用于减少重复整理和初稿编写工作，不替代人工审定。

可辅助生成的文稿包括：

1. 监理大纲初稿。
2. 质量问题分析报告。
3. 供应商质量问题统计说明。
4. 质量问题整改跟踪表。
5. 资料归档清单。
6. 重点风险提示清单。
7. 培训资料摘要和常见问题说明。
8. 阶段性质量复盘材料。

文稿生成流程建议如下：

1. 系统读取项目资料、问题台账和知识库内容。
2. 系统抽取结构化参数和统计结果。
3. 系统按模板生成文稿草稿。
4. 系统输出Word、Markdown、表格或图表。
5. 人工进行审核、修订、补充和确认。
6. 确认后的文稿进入正式资料链或归档流程。

该设计能够使AI功能与监造人员实际工作结合起来，体现“辅助查阅、辅助整理、辅助成稿”的业务价值。

#### 11. 人工复核与质量控制方案

本项目AI基础识别功能坚持“AI辅助、人工确认、结果留痕、责任可追溯”的原则。所有识别、抽取、统计、查询和生成结果均应进入人工复核环节，避免未经校核的信息直接进入正式业务数据链。

人工复核重点包括：

1. 字段复核。对项目名称、设备名称、位号、材质、规格、数量、标准依据、问题类别、关闭状态等字段进行人工确认。
2. 来源复核。核对AI输出是否能够回溯到原始文件、原始表格、原始页码或知识库资料。
3. 结论复核。对质量风险、整改建议、验收结论、放行建议、责任认定等专业内容进行人工判断。
4. 文稿复核。对监理大纲、质量问题报告、统计说明等文稿进行人工修订，确保内容符合项目实际和合同要求。
5. 归档复核。对AI建议的资料分类、归档字段和知识库标签进行人工确认。

风险控制措施包括：

1. 对识别置信度不足、字段缺失、来源不明确的结果进行提示。
2. 对关键业务字段设置必填项和人工确认状态。
3. 对AI初稿、人工修订稿和最终确认稿进行区分。
4. 对模型调用、文件输入、结果输出和人工确认过程进行日志记录。
5. 对涉及质量责任和验收判断的事项，不允许仅凭AI结果自动关闭或自动通过。

通过上述机制，AI功能能够提升效率，但不削弱质量管理的严肃性和可追责性。

#### 12. 与本项目现有模块的集成方案

AI基础识别功能不是独立于业务系统之外的单独工具，而是与本项目各业务模块协同使用。

1. 与数据信息资源库联动。AI识别结果、历史案例、标准资料和培训资料可进入资源库，形成统一检索入口。
2. 与资料归档模块联动。AI可辅助识别资料类型、提取关键字段、生成分类建议，提高归档一致性。
3. 与质量问题处理模块联动。AI可辅助分析质量问题清单、统计问题类别、识别重点供应商和未关闭问题。
4. 与统计分析模块联动。AI可将质量问题分析结果转化为图表和报告，为管理驾驶舱提供数据基础。
5. 与培训考试模块联动。AI可将历史问题、标准条款和常见问题沉淀为培训资料和题库参考。
6. 与权限和日志模块联动。AI处理过程按用户权限控制，文件上传、查询、生成和确认过程均可留痕。

上述集成方式能够使AI基础识别功能服务于监造业务全过程，而不是仅作为单独演示功能存在。

#### 13. 实施步骤与落地安排

本项目AI基础识别功能建议按阶段实施，保证能力可逐步验证、逐步上线、逐步优化。

第一阶段，环境部署与基础配置。完成本地DIFY部署、本地模型服务接入、文档解析服务部署、知识库基础环境配置、文件存储和日志审计配置。

第二阶段，资料识别工作流配置。完成PDF、Word、Excel、扫描件、图片附件等资料解析流程，配置字段抽取规则、关键页定位规则和结构化输出格式。

第三阶段，知识库建设与查询配置。导入标准规范、技术协议、历史案例、培训资料和项目经验资料，设置标签、切片规则、检索规则和问答提示词。

第四阶段，质量问题分析能力配置。配置质量问题清单表头识别、字段映射、统计分析、图表生成和报告导出流程，形成可复核的质量问题分析报告。

第五阶段，监理大纲和过程文稿生成配置。结合项目模板，配置参数抽取、JSON校验、Word回填和人工复核流程。

第六阶段，联调测试与试运行。使用本项目真实或脱敏资料进行测试，核验识别准确性、查询效果、报告完整性、人工复核流程和日志留痕。

第七阶段，优化完善与交付。根据试运行反馈优化提示词、字段规则、知识库标签、输出模板和人工复核页面，形成正式交付资料。
