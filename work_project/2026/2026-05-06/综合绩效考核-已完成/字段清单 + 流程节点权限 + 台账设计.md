# 字段清单 + 流程节点权限 + 台账设计

## 1. 设计范围

本文基于 `南京三方部门月度绩效考核标准.xlsx`，给出综合管理平台的详细落地设计，包含：

- 规则库字段设计
- 绩效打分单字段设计
- 流程节点权限设计
- 台账与报表设计

本文默认采用的业务模型为：

**规则库 + 事件式打分单 + 月度汇总台账**

即：

- 每一条加分/扣分事件对应一张打分单
- 月度结果通过台账自动汇总

## 2. 对象总览

建议在平台中建设以下 4 类核心对象：

| 对象名称 | 类型 | 作用 |
| --- | --- | --- |
| 绩效规则库 | 数据建模主表 | 维护所有加分/扣分标准 |
| 绩效打分单 | 流程表单 | 发起具体加分/扣分事件 |
| 绩效事件台账 | 数据建模台账 | 保存所有审批通过的打分事件 |
| 月度绩效汇总台账 | 数据建模台账/报表 | 汇总每人每月加扣分结果 |

另建议保留：

- 审批日志查询视图
- 员工个人绩效查询视图

## 3. 规则库字段清单

规则库用于承接 Excel 的两张 sheet。建议单独建一张基础表，不走审批流程。

## 3.1 规则库主表字段

| 字段编码 | 字段名称 | 控件类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `rule_code` | 规则编码 | 单行文本/自动编号 | 是 | 建议格式：`PF-ADD-0001`、`PF-DED-0001` |
| `rule_type` | 规则类型 | 下拉框 | 是 | `加分` / `扣分` |
| `source_sheet` | 来源Sheet | 单行文本 | 否 | `加分` / `扣分` |
| `dept_name` | 归属部门 | 下拉/数据选择 | 是 | 例如公司全体、执行部、综合部 |
| `line_name` | 归属条线 | 下拉/数据选择 | 否 | 例如数字信息条线、人事条线 |
| `rule_seq` | Excel序号 | 单行文本 | 否 | 保留原表序号，便于核对 |
| `role_scope` | 适用岗位 | 单行文本/下拉 | 否 | 例如全员、项目经理、区域经理 |
| `rule_title` | 规则标题 | 单行文本 | 是 | 建议取细分事项前 30-50 字作为标题 |
| `rule_detail` | 细分事项 | 多行文本 | 是 | 对应 Excel “细分事项” |
| `extra_condition` | 附加事项 | 多行文本 | 否 | 对应 Excel “附加事项” |
| `score_rule_text` | 分值规则原文 | 多行文本 | 是 | 对应 Excel 最后一列 |
| `score_model` | 分值模型 | 下拉框 | 是 | `固定值` / `区间值` / `累乘型` / `分档型` / `公式型` |
| `score_direction` | 分值方向 | 单选框 | 是 | `+` / `-` |
| `fixed_score` | 固定分值 | 数字 | 否 | 固定值规则时填写 |
| `min_score` | 最小分值 | 数字 | 否 | 区间值规则时填写 |
| `max_score` | 最大分值 | 数字 | 否 | 区间值规则时填写 |
| `unit_type` | 计算单位 | 下拉框 | 否 | `每次` / `每天` / `每节点` / `每人` / `每10万` 等 |
| `score_cap` | 分值上限 | 数字 | 否 | 如“上限25分”时填写 |
| `manual_confirm_flag` | 是否需人工确认分值 | 单选框 | 是 | `是` / `否` |
| `need_attachment` | 是否必须附件 | 单选框 | 是 | `是` / `否` |
| `need_remark` | 是否必须说明 | 单选框 | 是 | `是` / `否` |
| `enable_flag` | 是否启用 | 单选框 | 是 | `是` / `否` |
| `remark` | 备注 | 多行文本 | 否 | 规则维护说明 |
| `create_user` | 创建人 | 系统字段 | 否 | 系统带出 |
| `create_time` | 创建时间 | 系统字段 | 否 | 系统带出 |
| `update_time` | 更新时间 | 系统字段 | 否 | 系统带出 |

## 3.2 分值模型建议口径

| 分值模型 | 适用示例 | 系统处理建议 |
| --- | --- | --- |
| 固定值 | `每次扣2分` | 自动带出固定分值 |
| 区间值 | `每次加1-5分` | 人工填写实际分值，系统校验范围 |
| 累乘型 | `每延迟1个工作日扣0.5分` | 录入次数/天数，系统自动乘算 |
| 分档型 | `每次扣15/30分` | 需选择严重程度，再带出具体分值 |
| 公式型 | `每10万1分，上限25分` | 录入基数，系统按公式计算 |

## 4.2 字段联动建议

| 联动编号 | 条件 | 动作 |
| --- | --- | --- |
| `L01` | 选择 `rule_code` | 自动带出规则标题、细分事项、附加事项、分值规则、分值模型 |
| `L02` | `score_model=固定值` | 自动带出 `actual_score`，设为只读 |
| `L03` | `score_model=区间值` | `actual_score` 可编辑，并校验在 `min_score~max_score` 之间 |
| `L04` | `score_model=累乘型` | 显示 `occur_count` 或 `base_quantity` |
| `L05` | `score_model=分档型` | 显示 `severity_level` |
| `L06` | 规则要求附件 | `evidence_attachment` 设为必填 |
| `L07` | 审核节点填写 `review_adjust_score` | `score_result` 暂按审核分值预览 |
| `L08` | 审批节点填写 `approve_adjust_score` | `score_result` 以审批分值为准 |

## 5. 流程节点权限设计

## 5.1 推荐流程节点

1. `发起打分`
2. `归口审核`
3. `最终审批`
4. `结果通知`

## 5.2 节点权限表

| 节点 | 处理人 | 可编辑字段 | 说明 |
| --- | --- | --- | --- |
| 发起打分 | 各部门部长/分管领导 | `assessment_month`、`score_date`、`scorer_role`、`assessed_dept`、`assessed_line`、`assessed_role`、`assessed_employee`、`rule_code`、`base_quantity`、`occur_count`、`severity_level`、`actual_score`、`event_date`、`fact_desc`、`evidence_attachment`、`cross_dept_flag`、`source_ref_no` | 发起人负责选规则、填事实、传证据 |
| 归口审核 | 赵洵/许开明 | `review_decision`、`review_opinion`、`review_adjust_score` | 审核是否属实、分值是否合理 |
| 最终审批 | 陈琳 | `approve_decision`、`approve_opinion`、`approve_adjust_score` | 最终确认并决定是否生效 |
| 结果通知 | 系统节点 | 无人工编辑 | 写台账并通知被打分人 |

## 5.3 各节点只读字段

除当前节点可编辑字段外，其余字段建议均设为只读，尤其是：

- 规则带出字段
- 已审核意见
- 已审批意见
- 系统状态字段

## 5.4 节点处理建议

### 发起打分节点

- 必填：被打分人、规则、事实说明
- 如规则要求附件，则证据附件必填
- 如规则是区间值，实际分值必填并校验范围

### 归口审核节点

- 可通过、退回、驳回
- 可调整分值，但必须填写审核意见

### 最终审批节点

- 可同意、退回、驳回
- 如调整分值，审批意见必填
- 审批通过后写入最终分值

### 结果通知节点

- 自动写绩效事件台账
- 自动向被打分人推送消息

## 6. 路由与校验规则

## 6.1 路由规则

| 条件 | 流向 |
| --- | --- |
| 发起提交 | 归口审核 |
| 审核通过 | 最终审批 |
| 审核退回 | 返回发起人 |
| 审核驳回 | 流程结束 |
| 审批同意 | 结果通知 |
| 审批退回 | 返回发起人 |
| 审批驳回 | 流程结束 |

## 6.2 校验规则

| 编号 | 校验内容 |
| --- | --- |
| `V01` | `actual_score` 不可为空 |
| `V02` | 固定值规则下，`actual_score` 必须等于固定分值 |
| `V03` | 区间值规则下，`actual_score` 必须在最小值和最大值之间 |
| `V04` | 累乘型规则下，`occur_count` 或 `base_quantity` 必须填写 |
| `V05` | 规则要求附件时，附件必传 |
| `V06` | 被打分人不能为空 |
| `V07` | 同一员工、同一月份、同一规则、同一事件日期，如业务不允许重复，应提示校验 |

## 7.3 月度绩效汇总台账

该台账建议按“员工 + 月份”聚合。

建议表头：

| 字段名称 |
| --- |
| 考核月份 |
| 员工姓名 |
| 所属部门 |
| 所属条线 |
| 所属岗位 |
| 月度加分合计 |
| 月度扣分合计 |
| 月度净增减分 |
| 已审批加分条数 |
| 已审批扣分条数 |
| 最后更新时间 |

### 计算口径

- `月度加分合计 = 该员工当月所有已审批通过加分事件之和`
- `月度扣分合计 = 该员工当月所有已审批通过扣分事件之和`
- `月度净增减分 = 月度加分合计 - 月度扣分合计`

如后续制度明确基础分，可在此台账中增加：

- `基础分`
- `最终绩效分`

## 11. 本方案中的关键说明

### 11.1 推荐一事一单

本文推荐：

- 一条事件一张单
- 一条单只打一条规则

这是为了：

- 便于审批
- 便于通知
- 便于审计
- 便于追责

### 11.2 如后续业务坚持做“月度汇总单”

则可以扩展为：

- 主表：月份、部门、发起人
- 子表：被打分人、规则、分值、证据

但该方案会增加：

- 子表审批复杂度
- 逐人通知复杂度
- 台账拆分复杂度

因此不作为当前推荐方案。
