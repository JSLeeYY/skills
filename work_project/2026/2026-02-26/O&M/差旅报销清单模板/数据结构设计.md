# 差旅报销台账系统 - 数据结构设计


## 2. 费用分类体系

### 2.1 费用大类
- **差旅费** (Travel)
- **招待费** (Entertainment)
- **通讯费** (Communication)
- **培训费** (Training)
- **其他费用** (Others)

### 2.2 差旅费子类
- 国内差旅-餐费
- 国内差旅-住宿
- 国内差旅-交通
- 国内差旅-其他
- 业务招待费-餐费

### 2.3 状态定义
- **待提交**: 草稿状态
- **审批中**: 已提交待审批
- **已审批**: 审批通过
- **已驳回**: 审批驳回
- **已支付**: 财务已支付

## 3. 数据关系图

```
employees (员工表)
    ↓ 1:N
expense_records (报销主表) ← N:1 → contracts (合同表)
    ↓ 1:N
expense_details (费用明细表)
    ↓ 1:1
    ├── travel_details (差旅明细表)
    └── entertainment_details (招待费明细表)
```

## 4. 索引设计

### 主要索引
- `expense_records`: recordId (主键), employeeId, contractId, expenseDate, status
- `expense_details`: detailId (主键), recordId, expenseType
- `employees`: employeeId (主键), name
- `contracts`: contractId (主键)

## 5. 数据存储方案

### 方案A: JSON文件存储（轻量级）
```
/data
  ├── employees.json          // 员工数据
  ├── contracts.json          // 合同数据
  ├── expense_records.json    // 报销主表
  ├── expense_details.json    // 费用明细
  ├── travel_details.json     // 差旅明细
  └── entertainment_details.json // 招待费明细
```

### 方案B: SQLite数据库（推荐）
- 单文件数据库: `expense_system.db`
- 支持SQL查询和事务
- 更好的性能和数据完整性
